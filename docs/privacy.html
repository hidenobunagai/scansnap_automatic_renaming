ScanSnap Automatic Renaming

Privacy Policy

Effective date: 18 October 2026 · Last updated: 18 October 2026

1. What this app is

ScanSnap Automatic Renaming is a private, single-user Google Apps Script tool. It watches one Google Drive folder for scanned PDFs, reads their contents with OCR, asks an AI model to suggest a descriptive filename, renames and archives the files, and writes an entry to a Google Sheets log.

The app is operated by its owner, Hidenobu Nagai, for his own documents. It has no other users and no public interface. It is not submitted for Google OAuth verification, because Google exempts personal-use apps with fewer than 100 users.

2. Google user data the app accesses

The app acts only on the Google Account that authorized it. It requests these Google OAuth scopes and uses them as follows.

  • drive — read PDFs in the configured ScanSnap folder, rename them, and copy them into the archive folder. The app also creates and deletes a short-lived temporary Google Doc while running OCR.
  • documents — read the text of that temporary OCR document, which exists only for the duration of a single run.
  • spreadsheets — create and append to the log spreadsheet that records each processed file, its status, and the reason for the chosen name.
  • script.external_request — send an HTTPS request to the Google Gemini API so the model can suggest a filename.
  • script.scriptapp — create the time-based trigger that runs the job on a schedule.
  • script.send_mail — send a failure notification email to the owner, and only if the owner has configured a notification address.

The app does not access Gmail message bodies, Calendar, Contacts, or any Google data outside the scopes listed above. It does not read the Drive files of anyone other than the authorizing account.

3. How the data is used

The only purpose of the data is to produce a descriptive filename for the owner’s own scans.

  1. The PDF found in the ScanSnap folder is sent to Google Drive OCR.
  2. The extracted text is passed to the Google Gemini API together with a prompt describing the desired filename format. This is the only point at which document content leaves the Google Account. Because the Gemini API is a Google service, Google’s own API terms govern how Google processes that request.
  3. The model’s suggestion is validated, then used to rename the file and to file a copy in the archive folder.
  4. A row describing the outcome is appended to the log spreadsheet, so the owner can review what happened and correct errors.

The app does not use the data for advertising, profiling, or any purpose unrelated to renaming the owner’s scans.

4. Storage and retention

  • The app has no server and no database of its own. The developer does not receive, copy, or host any user data.
  • All artifacts — the original PDFs, the renamed files, the archive copies, and the log spreadsheet — stay inside the owner’s own Google Account and are governed by Google Drive and Google Sheets retention.
  • The temporary OCR document is deleted by the app at the end of each run, including on failure.
  • The API key used for the AI request is stored as an Apps Script script property inside the owner’s own Apps Script project. It is never transmitted anywhere except to the AI provider as part of the authorized request.
  • Data is kept until the owner deletes the files or the log. The owner can delete any of it at any time without involving the developer.

5. Sharing and disclosure

  • The app does not sell, rent, or trade Google user data.
  • The app does not transfer Google user data to any third party.
  • Document content is transmitted to the Google Gemini API solely to generate a filename, as described in section 3. No other external service receives it.
  • The app does not let humans read the data, except for the owner reading his own files and log.
  • No data is used to determine creditworthiness or for lending purposes, and no data is used for advertising or re-targeting.

Limited Use statement. The app’s use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

6. In-product privacy notice

The script runs unattended and has no end-user interface, so there is no in-app screen on which to display a notice. The outputs a person may see are the log spreadsheet, the renamed files, and — only if a notification address is configured — a failure email to the owner. This page is the app’s privacy notice and is linked from the app’s home page and from the OAuth consent screen.

7. Security

  • The script runs under the owner’s own Google Account, with the authorizations the owner granted.
  • Access tokens and API keys are kept in Google-managed storage (Apps Script properties), not in public files.
  • All network requests are made over HTTPS.
  • No credentials are embedded in this website or in the public source repository.

8. Revoking access and deleting data

  • Revoke the app’s access at any time at myaccount.google.com/permissions. The script stops working immediately afterwards.
  • Delete the renamed files, the archive copies, and the log spreadsheet directly in Google Drive and Google Sheets.
  • Delete the Apps Script project to remove the stored API key and the trigger.
  • Because there is no developer-side copy, deletion in the owner’s account is complete and requires no request to the developer.

9. Children

The app is not directed at children and is not made available to anyone other than its owner.

10. Changes to this policy

If the app’s data handling changes, this page is updated here, and the “Last updated” date above changes accordingly.
